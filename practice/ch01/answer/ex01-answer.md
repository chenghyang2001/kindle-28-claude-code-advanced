# 練習 01 解答 — 模糊指令 vs 結構化指令

## 實驗設定

| 項目 | 內容 |
| --- | --- |
| 執行方式 | `claude -p`（Claude Code 2.1.302），先清掉所有 `CLAUDE*` 環境變數；腳本 `scripts/run-prompt.sh` |
| 沙盒 | 每次把 `fixtures/notes/` 複製到 `runs/<run>/`，兩次執行互不干擾 |
| 範例資料 | `notes/` 內 4 個 `.txt`（含中文）＋ 子目錄 `archive/old.txt` ＋ `readme.md` |
| 刻意埋的陷阱 | ① 子目錄要不要算 ② 非 txt 檔 ③ `3-idea` vs `10-reading` 的排序 ④ 輸出放哪 |
| 我心中的預期 | 就是結構化版寫的規格：只算第一層 `.txt`、依檔名排序、`===== 檔名 =====` 分隔、輸出 `./out/merged.txt`、UTF-8 |
| 獨立驗證 | `scripts/check_merged.py` 依規格逐項檢查產物，不看 Claude 的自我回報 |

Prompt 原文：`prompts/ex01-vague.txt`、`prompts/ex01-structured.txt`（與題目一字不差）。

## 任務 1：模糊版「把這些 txt 合併」

- **Claude 反問回合：0**。`-p` 模式本來就不能互動，而且本專案 CLAUDE.md 要求「不要停下來問」，所以它選擇**自己猜**，最後附上一張「我自己決定了 5 件事」的表。
- 它做的 5 個決定：只合併第一層、排除 `readme.md`、**自然排序**（3 在 10 前面）、加檔名標頭＋段落空行、**輸出到根目錄 `merged.txt`**。
- 符合預期嗎？**部分符合**。輸出位置不對（我要 `./out/merged.txt`），所以補了第 2 回合：「輸出要放在 ./out/merged.txt」，它才搬過去。
- 注意：它排除 `archive/old.txt` 的理由是「檔案內容寫著不應被合併」——這是我範例資料洩漏了意圖，現實資料不會這麼好心。如果拿掉這句，模糊版很可能就把子目錄也合併了。

## 任務 2：結構化版

- **反問 0 回合、使用者 1 回合就完成**，輸出在 `./out/merged.txt`，檔數 4、總行數 15，終端也印了。
- `check_merged.py` 檢查：UTF-8 ✅、無 BOM ✅、檔數正確 ✅、排除子目錄 ✅、內容完整 ✅。
- **但仍有一個意外**：「依檔名排序」被解讀為**字串排序**，所以順序是 `01 → 02 → 10 → 3`。Claude 自己有在回報中點出這點並提議改自然排序。→ 結構化 prompt 也不是萬靈丹，「排序」這種詞要講清楚是字串還是自然排序。

## 任務 3：量化對照表

| 指標 | ❌ 模糊版 | ✅ 結構化版 |
| --- | --- | --- |
| 使用者需要下指令的回合 | **2**（原始＋返工） | **1** |
| Claude 反問回合 | 0（被迫自己猜） | 0 |
| 一次到位（符合預期規格） | ❌ 輸出位置錯 | ✅（排序除外，見下） |
| 需要返工 | 是，1 次 | 否 |
| Claude 自行做的假設數 | 5 個（需要人逐條確認） | 1 個（排序方式） |
| 工具回合 num_turns 合計 | 5 + 2 = 7 | 4 |
| 總耗時 | 51.3 + 35.9 = **87.2 秒** | **34.1 秒** |
| 成本（API 計價估算） | 0.790 + 0.860 = **US$1.65** | **US$0.76** |
| 驗收：排序 | 自然排序（剛好符合直覺） | 字串排序（字面符合、直覺不符） |
| 驗收：總行數 | 18（多了段落空行） | 15 |

原始數據：`runs/METRICS.md`。

## 結論：結構化指令省下的具體成本

1. **省下一整個返工回合**：耗時從 87 秒降到 34 秒（−61%），成本從 US$1.65 降到 US$0.76（−54%）。每次 `claude -p` 光是載入系統提示與專案設定就要約 US$0.75，所以**返工一次 ≈ 成本翻倍**，省回合就是省錢最直接的方式。
2. **省下「審查 Claude 的假設」的人力**：模糊版產出時附了 5 條假設，人要一條條判斷對不對；結構化版只剩 1 條。
3. **讓結果可驗收**：有了「輸出位置、分隔格式、編碼、要印出什麼」，我才能寫 `check_merged.py` 自動驗；模糊版沒有標準，只能用眼睛看「好像可以」。
4. **但結構化 ≠ 零歧義**：「依檔名排序」就出事。寫成功標準時要附**一個具體例子**（例：「`3-idea` 要排在 `10-reading` 前面」），比形容詞更不會被誤讀。
5. 模糊版這次「看起來還不錯」，是因為模型很會猜加上範例資料洩漏提示；這種運氣不能當成流程。
