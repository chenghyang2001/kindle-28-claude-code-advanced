# 練習 02 解答：用 agent debate 過濾爭議決策（實際派 3 位審查者）

完整紀錄：`reports/04-debate.md`；修正結果：`reports/05-fix.md`。

## 爭議決策從哪來
練習 01 的審查 agent 找到一條必改：`priority=None` 會讓 `sorted_items()` 當掉。修法有兩派：
- **方案 X（受審）**：priority 不合法就靜默改成 3，程式永不當掉。
- 方案 Y（對照）：寫入端嚴格驗證並拋 ValueError；讀到壞資料時拋錯並附 id。

X 看起來很「貼心」（不會當掉），正是練習要過濾的「看似對其實錯」。

## 任務 1：三個對抗角度與提問

| 審查者 | 角度 | 要求必須回答的問題 |
| --- | --- | --- |
| R1 | 正確性 | 靜默修正會不會改掉使用者的意圖（"1" 變 3）？bool 是 int 的子類別怎麼處理？資料問題被掩蓋後多久才會被發現？ |
| R2 | 安全性與穩健性 | 一筆被竄改的 JSON 能不能讓整份清單無法顯示（DoS）？吞錯對稽核的影響？錯誤訊息會不會洩漏內容？ |
| R3 | 可維護性 | 與既有 `_parse_due`（壞格式就拋錯）一致嗎？行為能從程式碼與測試看懂嗎？日後改成嚴格的遷移成本？ |

執行方式：3 個 general-purpose 子代理**在同一則訊息平行派出**，彼此看不到對方的意見；都是只讀，只能用 `python -B -c` 做記憶體實驗。回傳格式固定為 `VERDICT / 理由 / 替代建議`。

## 任務 2：多數決與每位審查者的判斷

裁決規則：≥ 2 票反對就打回。

| 審查者 | 判斷 | 理由摘要（附實驗） |
| --- | --- | --- |
| R1 正確性 | 反對 | `'1'`、`1.0`、`True`、`-1`、`0` 全被改成 3，最高優先變中段；`sorted([True,2,1,False])` → `[False, True, 1, 2]`；壞值被 save() 永久寫進 JSON |
| R2 安全性 | 反對（附帶意見） | 寫入端吞錯 = 吞掉竄改跡象；`-999` 會插隊排第一；但指出方案 Y 在讀取端也有 DoS，且 `{value!r}` 印原值有 log 污染風險 |
| R3 可維護性 | 反對 | 一個模組兩套壞資料規則；X 需要一堆特例與測試；先寬鬆後改嚴格是破壞性變更 |

**結論：3 票反對、0 票贊成 → 方案 X 打回，採方案 Y 並合議補強：**
1. None 明確定義為預設值 3；bool、非 int、< 1 拋 ValueError 並附 id（R1）。
2. `add()` 在寫入端驗證（三位共識）。
3. 錯誤訊息只印 id 與型別，不印原值，`_parse_due` 一併改（採納 R2）。
4. 少數意見：R2 主張讀取端 fallback 3 + logging 以防 DoS，未達多數 → 不採納，列為已知風險（單人本機檔，明確報錯比默默排錯更好修）。

**落地驗證**：派實作 agent 修正 → `23 passed`；冒煙實驗 `None→3`、`'1'/True/-1` 都被拒絕，訊息為「id=6 的 priority 不合法（型別 str）」。git diff 只有 src/、tests/。

## 延伸思考

**多 agent 何時優於單 agent？**
- 需要「獨立判斷」時：本例 3 位審查者看不到彼此的意見，各自從自己的角度得出反對，獨立的一致比單一 agent 自問自答可信。
- 需要不同角度的「新鮮 context」時：R2 想到 DoS 與 log 污染，這是正確性角度不會主動去看的。
- 上游可能出錯時：練習 01 的研究算錯排序，被 context 乾淨的實作 agent 照合約擋下。
- 不適合：小改動、單一明確答案（例如修 typo），派 3 個 agent 只是燒 token。

**協調成本藏在哪？**
1. **Context 同步**：每個子代理要重讀合約、程式碼、報告（本次每個子代理約 10.5 萬 tokens，大多是重複的系統 context）。
2. **交付物落地**：只讀 agent 不能寫檔，主 agent 要負責把回傳存成 reports/，才能交給下一棒。
3. **整合衝突**：研究 vs 實作的排序衝突、R2 的少數意見，都要主 agent 讀懂並裁決，這部分無法外包。
4. **驗證成本**：每一棒都要跑 git diff、重跑測試；判斷 `.claude/`、`.pyc` 是誰產生的還要看時間戳。
5. **等待序列化**：研究 → 實作 → 審查必須照順序；只有 debate 的 3 位審查者能平行。
